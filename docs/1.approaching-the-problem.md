# Approaching the Problem

## Problem Statement

Write a program that automatically guesses random words. Connect to an API that plays a Wordle-like puzzle. You can
find the API documentation here: https://wordle.votee.dev:8000/redoc

## Requirements Analysis

### Problem 1: Understanding Wordle Rules

- Wordle is a word guessing game typically consisting of 5-letter words.
- The player has 6 attempts to guess the secret target word.
- Each guess must be a valid, meaningful word from the allowed word dictionary.
- Guess results are indicated with colors/states:
  - **Green (`correct`)**: Letter is in the word and in the exact correct position.
  - **Yellow (`present`)**: Letter is in the word but in the wrong position.
  - **Gray (`absent`)**: Letter is not in the word (or exceeds the count).

### Problem 2: Connecting with the API

Connect to the API to retrieve guess evaluations. API documentation is located at: https://wordle.votee.dev:8000/redoc

#### API Specification Analysis

The service provides 3 main endpoints:

- **Daily Word Guess API**: Checks guesses against the daily puzzle word.
- **Random Word Guess API**: Checks guesses against a random word (optional seed).
- **Target Word Guess API**: Creates/specifies a secret target word and checks guesses against it.

The API returns a JSON array structured as follows:

- An array of items corresponding to each letter slot. Each object contains:
  - `slot`: 0-indexed position of the letter (e.g. 0–4 for a 5-letter word).
  - `guess`: The single guessed character in lowercase.
  - `result`: Feedback status (`"absent"`, `"correct"`, or `"present"`).

```json
[
    {
        "slot": 0,
        "guess": "c",
        "result": "absent"
    },
    {
        "slot": 1,
        "guess": "r",
        "result": "correct"
    }
    // ...
]
```

### Problem 3: Automated Wordle Solver Algorithm

The solving algorithm must adhere to game constraints:

- Guessed words must match the required length (e.g., 5 letters).
- Guessed words must be valid dictionary entries.
- Guessed words must satisfy accumulated constraints from previous feedback.

#### Algorithm Workflow

1. **Strategic Starting Word**:
   Start with a high-entropy seed word containing common vowels and consonants (e.g., `crane`, `roam`).

2. **Feedback Analysis**:
   Parse the API feedback after each guess (`correct`, `present`, `absent`).

3. **Candidate Filtering (`matches_feedback`)**:
   - `correct`: Keep only candidate words that have the exact same letter at that specific slot.
   - `present`: Keep only candidate words containing the letter, but eliminate candidates having that letter at the current slot.
   - `absent`: Eliminate candidate words containing that letter (accounting for letter frequencies if the letter also appears as `present` or `correct`).

4. **Next Guess Decision**:
   Select the highest-information candidate based on letter frequency distribution and submit to the API until solved.

### Problem 4: Visualizing the Solving Process

The visualization includes:

- Displaying guessed words in a real-time Wordle-style animated board.
- Revealing color-coded feedback with 3D tile-flip transitions.
- Tracking attempt counts, remaining candidate search space, and letter frequency distributions.

Custom control components are added:
