# Giải quyết vấn đề

## Tạo dữ liệu các word

Dữ liệu các word tiếng anh được lấy về từ open source trên GitHub. Nguồn các word tiếng anh: https://github.com/dwyl/english-words
Lí do chọn nguồn này vì đây đây là nguồn được update gần nhất tính ở thời điểm hiện tại.

Sau khi lấy dữ liệu về thì tiến hành xử lý dữ liệu:

1. Đánh giá dữ liệu

- Dữ liệu là một file JSON với cấu trúc gồm có key là word và value mặc định là 1
- Các word được viết dưới dạng chữ viết thường
- Dung lượng file khá to (~6.8MB)

2. Xử lý dữ liệu

- Vì dữ liệu khá to, do đó, dữ liệu cần được xử lý phù hợp để có thể sử dụng hiệu quả
- Tiêu chí xử lý dữ liệu như sau:
  - Các word có thể truy xuất nhanh chóng theo số lượng
  - Các word có thể tìm kiếm nhanh chóng theo chuỗi ký tự
- Các bước xử lý dữ liệu:
  1. Phân cụm dữ liệu thành các nhóm có cùng số lượng ký tự
  2. Sau khi phân cụm theo số lượng ký tự, sẽ tiến hành chia file raw_words.json thành các file nhỏ hơn tương ứng với số lượng ký tự.
- Việc chia nhỏ file giúp cho việc tìm kiếm và xử lý dữ liệu dễ dàng hơn, từ đó giảm thiểu tài nguyên và thời gian xử lý

## Giả lập API để lập trình

Giả lập API ở môi trường local để không gây ảnh hưởng tới môi trường production. Bộ API gồm có 3 endpoint

- `/api/v1/daily`: API kiểm tra đáp án đoán từ mỗi ngày
- `/api/v1/random`: API kiểm tra đáp án đoán từ ngẫu nhiên
- `/api/v1/word/{word}`: API tạo từ cần đoán và kiểm tra đáp án

Bộ API giả lập sẽ có flag {{TEST_MODE}} trong `.env` để kích hoạt chế độ kiểm thử. Ở chế độ này, API sẽ trả về thêm dữ liệu word trong phần header để kiểm tra tính đúng đắn của API

## Thiết lập thuật toán ban đầu

### 1. Thuật toán chi tiết

- **Khởi đầu chiến lược**: Mặc định sử dụng từ `"crane"` (hoặc từ có tổng điểm tần suất chữ cái cao nhất cho từ độ dài khác 5, hoặc từ do người dùng truyền vào).
- **Phản hồi & Lọc ứng viên (`matches_feedback`)**:
  - `correct`: Giữ lại các từ có chữ cái trùng khớp chính xác tại vị trí (slot) đó.
  - `present`: Giữ lại các từ có chứa chữ cái đó nhưng loại bỏ các từ có chữ cái tại vị trí hiện tại.
  - `absent`: Loại bỏ chữ cái nếu không xuất hiện ở vị trí khác; nếu chữ cái có xuất hiện cả ở trạng thái `present`/`correct`, khống chế số lượng ký tự chính xác.
  - Lặp lại quá trình phản hồi và lọc ứng viên

```pseudocode
current_guess = "CRANE" // Từ khởi đầu

result = HTTP_GET(https://wordle.votee.dev:8000/daily?guess={{current_guess}}) // Or another API in API Documentation

while CheckResult(result) is not correct:
  absent_slot = [1, 2] // Example word is absent

  current_guess = ChooseGuessWord(current_guess, absent_slot) // Replace absent_slot to another word

  result = HTTP_GET(https://wordle.votee.dev:8000/daily?guess={{current_guess}})

print(current_guess)
```

### 2. Request & Response mẫu

Thuật toán tự động giải câu đố Wordle đã được triển khai hoàn chỉnh tại endpoint:

- `GET /api/v1/resolve`

API tự động điều hướng theo flag cấu hình `TEST_MODE`:

- Khi `TEST_MODE=true`: Sử dụng evaluator nội bộ local để kiểm thử độc lập, nhanh chóng.
- Khi `TEST_MODE=false`: Gửi request trực tiếp đến API ngoài `https://wordle.votee.dev:8000`.

#### Request (`GET /api/v1/resolve?mode=daily&size=5&starting_word=crane`)

```bash
GET /api/v1/resolve?mode=daily&size=5&starting_word=crane
```
